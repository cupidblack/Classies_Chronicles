## 1. Evidence classification and truthfulness

Evidence state for a field must be one of: `OBSERVED_REAL_PIXELS`, `MEASURED_FILE_BYTES`, `VERIFIED_SOURCE_TEXT`, `USER_VISUAL_FEEDBACK`, `DOCUMENT_SPECIFICATION`, `SYNTHETIC_TEST_ONLY`, `NOT_RUN`, `NOT_CHECKED`, `UNVERIFIED`, `BLOCKED`. Each QA assertion records what it actually establishes. A browser preview or screenshot is **not** proof of native source dimensions; a 1080×1920 resampled crop is not necessarily native 1080×1920 generated illustration; a beautiful four-quadrant composition is not automatically four 9:16 pages. A validated page count is not a passed continuity test. A passed editorial scene check does not prove rights, archive commit or publication.

**Real current observation:** `/mnt/data/a_detailed_comic_book_style_multi_panel_illustrati.png` was opened as actual local pixels and measured 1024×1536. For four equal zero-gutter quadrants its geometric cell dimensions are 512×768. This is 2:3, not strict 9:16. It may be used as the explicitly liked style and character anchor, but its C11 geometry for strict release cannot be marked PASS. All later generated composites previously rejected by the user are excluded from accepted P05–P16 inventory. The S01 first graphic's exact visible text and real-world sign details still require manual source check; visual preference is not blanket factual approval.

## 2. State machines and acceptance cursor

### 2.1 Independently measured status dimensions

`COMMISSION`: `AUTHORIZED / NOT_AUTHORIZED`; `SOURCE`: `LOCKED_REVISION / STALE / UNVERIFIED`; `STORYBOARD`: `LOCKED / NEEDS_REVIEW / NOT_CREATED`; `ASSET`: `NOT_STARTED / RENDERED_DRAFT / LETTERED / REPAIRED / FILE_MISSING`; `VISUAL`: `NOT_CHECKED / LOOK_REFERENCE_ACCEPTED / PAGE_QA_PASSED / FAILED`; `GEOMETRY`: `NOT_MEASURED / PAGE_RATIO_PASSED / FAILED / EXCEPTION_AUTHORIZED`; `CONTINUITY`: `NOT_CHECKED / PASS / FAIL`; `EDITORIAL`: `NOT_APPROVED / PROVISIONAL_WORKING_ACCEPTANCE / ACCEPTED`; `RIGHTS`: `UNVERIFIED / AUTHORIZED / RESTRICTED`; `PERSISTENCE`: `LOCAL_FILE_VERIFIED / COMMIT_VERIFIED / NOT_VERIFIED`; `RELEASE`: `NOT_AUTHORIZED / RELEASE_APPROVED / PUBLISHED_VERIFIED`.

A successful image tool output moves only `ASSET` to `RENDERED_DRAFT`. It does **not** advance `next_sheet` until the permitted reviewer has accepted that specific sheet for continued storyboarding. Even with a visually accepted image, rights and geometry may remain blocked for publication. No hidden or future operation is promised when the user has not issued the next continuation.

### 2.2 Run inventory that must exist before image rendering

The live run manifest must contain exact `run_id`; `source_uri` and `source_digest` when measured; `source_revision`; `commission_date`; `selected_master_edition`; `target_pages` and `target_sheets`; `stepping_mode`; `accepted_visual_anchor_image` path or accessible attachment; `visual_anchor_native_dimensions` if measured; `script_beats` P01…PN with nonduplicate source span/purpose; `character_look_cards`; `rights_status`; `challenge_source_text` stored in controlled private data **but supplied only to final PN**; `page_records` with actual accepted/rejected versions; `sheet_records` with four ordered P IDs and real file links; `continuity_checkpoint`; `next_page_cursor`; `next_sheet_cursor`; `user_accepted_boundary`; per-gate results; and file checksums where actually calculated.

## 3. Mandatory per-sheet preflight, inspection and stop conditions

### 3.1 Before Sxx

- The four planned page IDs are exactly the cursor's next four, with no restart; all 4 have distinct visual beats and source spans.
- Previous accepted **visual** reference and continuity capsule have been loaded and compared; character references show face, hair, wardrobe, props and location.
- Four current page records are explicit in the renderer request; earlier pages appear only as short continuity reference, future P pages are excluded.
- P/H/F physical vs historical vs computed is consistent; no fabricated authority, archival access, evacuation route, government status or mission relocation.
- `challenge_allowed=false` for every sheet before final; the exact Challenge A question is not exposed to those image calls.
- The renderer's likely native output geometry is known or the four-real-page assembly fallback is chosen; native quality not guessed.
- If any required public-portrayal consent is unverified, the asset is marked **provisional fictional** and cannot be automatically published.

### 3.2 After Sxx, before accepting/advancing

- Exactly **one** image composite is produced in the selected `SHEET_STEP`; its layout is two equal columns and two equal rows, all cells internally read as complete comic pages.
- Identity: exact four P IDs once in TL/TR/BL/BR; no cover-only quadrant, no 3/6/8 page mismatch, no duplicated adjacent stories.
- Visible story: specific change from previous accepted P and causality across all four; correct speakers, clothing, hair, props, place, time-of-day, emotional arc, and no recap/reboot.
- Pixel geometry: the image and each cell measure 9:16; no aspect stretching/cropping, no virtual padding presented as native, source-vs-export size disclosed. For 1080×1920 genuine pages: combined sheet 2160×3840.
- Quality: inspect 4 actual cells at their expected phone crop, bubble tails and text, anatomy, hands, evidence labels, time/location, skin/hair, meaningful backgrounds, no unrelated titles/extra gutters.
- Proof text: dates, visible names, sign details, authorization status and source-critical wording are accurate; if deterministic lettering used, inspect **final post-composite raster**.
- Challenge: **0** occurrences on any page P1…P(N−1), including “Classies Challenge”, disguised quizzes, “Key Takeaway” or unrequested closure boxes; **exactly 1** complete public Challenge A at literal bottom of PN and nothing after it.
- If fail: mark Sxx `REPAIR_REQUIRED`, retain cursor and revise same P/S IDs; if pass working owner acceptance, store last scene/character states, actual image link, revisions, next four page records, QC note privately and STOP.

## 5. Geometry, pixel and file checks (mechanical vs human)

For zero-gutter images `page_size=(W,H)`, `sheet_size=(2W,2H)`, with `16W=9H`. Test cases: page 1080×1920→sheet 2160×3840 = compliant; page 540×960→sheet 1080×1920 = compliant ratio **but below native resolution target**; observed original first sheet 1024×1536→cell 512×768 = ratio **FAIL**. A 2×2 sheet cannot be called compliant merely because the image-model prompt said “9:16.”

A helper validator may calculate: file exists and opens; PNG/JPEG format; intrinsic width/height; exact ratio; cell coordinates; file SHA-256 and decoded RGBA pixel SHA-256; identical duplicate pixels; simple perceptual near-duplicate *review flags*; expected P/S count and missing ID list; correct assembly through lossless pixel copy. It **cannot** certify correct character likeness, meaningful story beats, absence of all AI-hallucinated text, challenge-source fidelity, consent or release. A synthetic validator test is only a check of the utility's arithmetic.
