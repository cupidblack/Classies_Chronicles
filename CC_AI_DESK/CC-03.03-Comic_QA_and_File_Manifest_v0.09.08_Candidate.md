## 1. Required QA evidence and meaning of PASS

Distinguish these evidence types, never flatten them into “looks good”:

- `OBSERVED_REAL_PIXELS`: opened and visually inspected the actual raster, not only a website preview or model promise.
- `MEASURED_FILE_BYTES`: actual file existed; width/height/format/digest measured locally.
- `VERIFIED_SOURCE_TEXT`: exact selected source and section text was directly readable.
- `SOURCE_CONTEXT_ONLY`: source description, historical report, or search excerpt, without exact bytes.
- `USER_VISUAL_FEEDBACK`: a user accepted/rejected a specific visual aspect of a specific page/sheet.
- `DOCUMENT_SPECIFICATION`: rule exists in a prompt, not proof a renderer obeyed it.
- `SYNTHETIC_TEST_ONLY`: utility was tested against nonstory fixtures; cannot certify the real comic.
- `NOT_RUN`, `NOT_CHECKED`, `NOT_AVAILABLE`, `UNVERIFIED`, `BLOCKED`: unresolved or unavailable evidence.

Allowed QA outcomes per gate: `PASS`, `FAIL`, `BLOCKED`, `NOT_CHECKED`, `NOT_APPLICABLE`. Only show `PASS` when actual evidence supports the gate's **entire scope**. User-liked character style is not rights clearance; 9:16 on a resized output is not proof of 1080×1920 native illustration; eight page IDs is not proof of eight distinct causal beats.

State axes (orthogonal): `COMMISSION`; `SOURCE`; `STORYBOARD`; `COVER`; `ASSET`; `VISUAL`; `GEOMETRY`; `NATIVE_DETAIL`; `CONTINUITY`; `EDITORIAL`; `RIGHTS`; `PERSISTENCE`; `RELEASE`. Example: `ASSET=RENDERED_DRAFT`, `GEOMETRY=PASS`, `NATIVE_DETAIL=UNVERIFIED`, `RIGHTS=UNVERIFIED`, `RELEASE=NOT_AUTHORIZED` can all be true for the same file.

## 2. Pre-render file and storyboard contract

A comic issue may not call a narrative image render until the following **can be populated from real plans and verified sources**:

| Required item | Check |
|---|---|
| Source | `Output A` chosen file, revision, source/rights status, optional real SHA-256 |
| Scope | Official season/chapter/episode/daily IDs, titles, whether this is first day of episode |
| Page count | **N8 default**, **N4 when very short and documented**, explicit N=4k overrides, N frozen |
| Page identity map | Exactly `P01…PN`, each with unique chronological source beat and scene function |
| Sheet map | Exactly `S01[P01–P04]`, `S02[P05–P08]` ...; `N/4` sheets |
| Geometry | Real page, sheet and four palette pixel dimensions; fixed cell boxes; no gutters |
| Header | P01 episode 25–33⅓%, daily 20–25%, or **combined first-day 25% exactly**; all are scene-bearing |
| Logo | Actual selected Classies identity asset, approved usage, no repeated wordmark text |
| Covers | Separate per-season and per-chapter 9:16 register and scoped title; never a P cell |
| Source-critical details | P/H/F clocks, date/locale, actors, wardrobe, evidence states, safety/permissions, Scripture and news provenance |
| Challenge | Correct public Challenge A source only on eligible final PN; absent or restricted challenge never invented |
| Previous visual | Prior owner-accepted S / visual reference or explicit first-run source |
| Continuity capsule | Last panel, character looks, room, props, unresolved claims, next cursor |
| Native capability | Actual provider/tool supported sizes and its planned restoration/finishing path; not assumed |
| Permissions | Real character/brand/third-party rights status and provisional/publication limitations |

A missing approval does not automatically stop a user-authorized private provisional concept; it does block a false claim of public-clearance. A missing **essential story** or exact selected source requires a source-controlled stop before claiming a faithful comic adaptation.

## 4. Exact geometry and header inspection tests

### 4.1 Mechanical pixel invariants

Let final page file be `(Wp,Hp)` and sheet file `(Ws,Hs)`, with **zero gutters**. Require:

```text
Wp >= 1080
Hp >= 1920
16 * Wp == 9 * Hp
Ws == 2 * Wp
Hs == 2 * Hp
16 * Ws == 9 * Hs
N >= 4 and N % 4 == 0
page_count == N
sheet_count == N // 4
all 4 extracted quadrants equal expected source pages pixel-for-pixel
P-order: TL, TR, BL, BR, strictly increasing
```

**Default premium**: P = 2160×3840, S = 4320×7680; TL `[0,0,2160,3840]`, TR `[2160,0,4320,3840]`, BL `[0,3840,2160,7680]`, BR `[2160,3840,4320,7680]` (exclusive right/bottom). **Minimum export**: P =1080×1920, S=2160×3840. An external image provider may not be capable of directly rendering this geometry; the fixed-size master palettes and compositing tool define the post-render deliverable and must be accompanied by truthful native-origin records.

**Forbidden acceptance shortcuts**: `resize((2160,3840))` from a 512×768 2:3 picture; crop away character limbs/captions to fit; leave huge white bands around low-res content; copy four identical panels into four cell positions; wrap one tall poster in 2×2 borders and claim four pages; count a one-page 1080×1920 sheet as containing four minimum-size pages.

If a source is reconstructed/outpainted from smaller/ratiometrically wrong art, record source dimensions and method, inspect genuine content near all four page edges, compare to accepted reference and source dialogue, and separately mark final export dimensions. Upscaling alone cannot establish native/resolved detail. A source image with high displayed resolution but unusable text is still a C13/C19 failure.

### 4.2 P01 header checks

For each relevant page P01, measure the intended graphic design-region height—not decorative glow bleeding into the scene; detect visible header anchors and preserve the first source action.

| First-page use | Valid intended header fraction of page height | Information that may appear | Forbidden |
|---|---|---|---|
| Standalone episode P01 | 25%–33⅓% | Chosen logo once, official episode title, scene motifs; season/chapter/episode folio | Duplicate brand name, unrelated synopsis, cover-only P |
| Daily chronicle P01 on subsequent episode day | 20%–25% | Logo once, episode title, scene motifs; daily folio | Extra storyless intro page, repeated logo |
| Daily P01 also first day of episode | **Exactly 25%** | **One** blended header; longer chronicle folio | Stacked episode + day headers |
| P02…PN | No large opening header | Compact folio and in-story labeling only | New episode-cover opening on every sheet |

For a 3840px page: episode header **960–1280 px**; daily header **768–960 px**; combined exactly **960 px**. For 1920px: episode **480–640 px**, daily **384–480 px**, combined **480 px**. Header height alone is insufficient: check the actual first scene/action remains visible and causally connects to P02. Exact chosen logo must not be duplicated as plain `CLASSIES CHRONICLES` text. Follow the correct source role for the Koware Group mark (in-world only).

**Visible folio tests** (for current-issue example):

```text
Episode-only: Season 00 - Chapter 05 - Episode 03  01/08
Daily issue:  Season 00 - Chapter 05 - Episode 03 - Chronicle #05  01/08
Last page:    Season 00 - Chapter 05 - Episode 03 - Chronicle #05  08/08
```

Page 1 folio may be at top or bottom. On the final P(N), folio must be **top**, if Challenge A occupies the literal bottom. The example does not authorize changing 16-page jobs to `01/08`; for such a job use `01/16` through `16/16`.

### 4.3 Standalone season/chapter cover checks

For each **commissioned** season or chapter cover, require: full standalone 9:16 >=1080×1920 measured pixels, preferred 2160×3840; correct approved level title and hierarchy; selected Classies logo once; original artwork with uncluttered motif and readable title; no Koware corporate logo as co-brand; no source-only daily detail passed off as full-season identity; independent asset ID and owner reuse decision. A cover does **not** appear in P01…PN, an S quadrant or the Challenge A count. If a cover is not yet commissioned/available mark `COVER_PENDING` or `NOT_COMMISSIONED` accurately rather than invent its file or treating the whole comic as automatically published.

## 6. Per-step checkpoints, repair and acceptance cursor

### 6.1 Before the next `Sxx`

Validate current selected A, frozen `N`/`N/4`, exactly next four P IDs and beats, correct scene summary from prior accepted page, actual image references, palette files/coordinates, expected header/challenge state, and rights. Confirm the new sheet does **not** repeat the episode opener, reopen an intentionally sealed archive or imply an unapproved physical probe-team return. For `S01` assert P01 actual first-scene action and integrated header; for later S no large repeated mastheads. Maintain a per-turn `challenge_allowed=false` until the final page is actually included.

### 6.2 After actual page rendering / before assembly

Measure each **real file**, inspect 9:16 and final resolution, check the four are not identical copies, verify readable proof text and the four planned beats. If non-9:16, **do not directly place into a stretched fixed palette**. Rebuild/reframe via an authorized content-preserving high-resolution scene workflow and recheck; if not possible mark `BLOCKED_GEOMETRY`. If just an upscale, register `EXPORT_RESOLUTION_PASS / NATIVE_DETAIL_UNVERIFIED`, not native PASS.

### 6.3 After assembly

Measure final composite; exact rows/columns, four row-major pages, actual cell-box pixel equality to page inputs; compare visual transitions and safe gutters (none between cells beyond page's own native margins). Inspect at 100% and smartphone-size. Record manifest and local file integrity evidence; never report media/video ready merely because pages exist.

### 6.4 Failure, owner input and finalization

On any hard fail: hold `next_sheet_cursor`, record `REPAIR_REQUIRED`, preserve old file and selected visual reference, generate `r02` for the same S/P IDs. On full working acceptance, save the last-scene capsule and set `WAIT_FOR_USER`. An owner may accept a look but withhold geometry approval; this advances **only** the specifically accepted state and cannot cause publication. On user `continue`, use the accepted latest cursor, no earlier P IDs. Only after final PN, or a major blocker, create one consolidated human-readable QA/handover document and actual file manifest; no interim extra cover PDFs/reports in an ordinary `SHEET_STEP` response.

## 7. Human editorial and release review (not automatable by pixels)

The mechanical geometry tool cannot certify: accurate full-scene narrative, safe depiction of real hazards, religious verse meaning, responsible historical reporting, fully correct dialogue, image originality, likeness rights, character appearance consistency, nuanced emotion/pacing, or whether the comic's first-page cover aesthetic is effective. Visual and editorial QA must inspect the real image and the selected manuscript. The reviewer should confirm that the story's 20–33% field-team allocation where prescribed remains evident at issue scale, that narration does not turn broadcast news into fictional evidence, and that unresolved legal/technical inquiries are not solved by graphic dramatization.

Clear categories separately: `WORKING_ART` / `COMIC_TEXT_PROOFED` / `GEOMETRY_ACCEPTED` / `NATIVE_DETAIL_ACCEPTED` / `CANON_CHECKED` / `RIGHTS_AUTHORIZED` / `RELEASE_APPROVED` / `PUBLISHED_VERIFIED`. Only true publication evidence permits the last state. No production QA file should expose internal Challenge C answers or private B1–B8 beyond a permission-controlled internal handover.

## 8. Validator usage and QA evidence of this candidate

The additional standalone file `cc03_collage_geometry_v0.09.08.py` provides:

- `prepare`: exact premium/selected-size transparent **sheet palette** plus **four separate page palettes** and a geometrical guide preview/contract file.
- `inspect`: read an existing composite and check actual size/ratio and expected cell geometries; cannot prove it truly contains four different story pages without four source pages or human inspection.
- `assemble`: accept exactly four existing **same-size, exact-9:16, >=minimum-size** page files and place them into 2×2 RGBA canvas by pixel copy; reject repeated identical source paths or identical decoded pixel contents and reject overwrites; optionally extract/verify cells and save real file metadata/digests.
- `selftest`: create synthetic quadrants (small 90×160 geometry fixtures) and exercise expected arithmetic and pixel-preserving row-major assembly. This proves **validator correctness only on synthetic fixtures**, not a real illustrated comic's narrative, native detail or permissions.

Example execution commands:

```bash
python cc03_collage_geometry_v0.09.08.py selftest
python cc03_collage_geometry_v0.09.08.py prepare --out palettes --page-width 2160
python cc03_collage_geometry_v0.09.08.py assemble --output sheet.png --pages p01.png p02.png p03.png p04.png
python cc03_collage_geometry_v0.09.08.py inspect --sheet sheet.png --page-width 2160
```

The above are **instructions**, not claims about pages `p01.png` to `p04.png` existing. In a real run the validator's report must be stored as actual evidence attached to a page/sheet ID, using real dimensions and file hashes. The selftest result, if executed in this package, may be documented in an accompanying integrity report but must not be counted as a C11 pass for any future comic artwork.

## 9. Candidate conclusion and pending integration

`CC-03.03 v0.09.08` specifies the mechanism to prevent the prior 2:3 aspect error, repeated headers, wrong page counts, missing story beats and falsely inferred native resolution. The three-file set is internally written as a candidate, preserving inherited C01–C22 and a strict `WAIT_FOR_USER` creative boundary. It **does not certify any real episode art/covers as compliant**, does not change published episode history, does not establish consent or publisher authority, and cannot claim exact full-main-v0.09.05 comparison until that inaccessible file is recovered and reconciled.
