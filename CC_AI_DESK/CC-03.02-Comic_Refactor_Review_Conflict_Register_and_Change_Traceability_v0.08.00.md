## 1. Executive determination

**Retain a dedicated Master Comic Generation Prompt.** The Unified Production Master defines authority, narrative boundaries, derivative triggering, three clocks, 19 logical families and twenty-two C gates, but is not an adequate substitute for per-page art direction, cinematic transitions, source-to-beat coverage, lettering, renderer limits, mobile safe zones, native collage geometry, physical slicing, pixel evidence and derivative QA. The daily protocol produces source prose. The ledger safeguards accepted continuity and independent editorial states. The comic specialist **adapts**, and the review record **explains changes**. None substitutes for the other.

The user's new mobile-first requirement supports **16 complete individual 9:16 portrait pages as this proposed specialist's standard**, replacing the v0.04.00 five-page default after *effective adoption*. The 4×4 single collage is a **conditional preferred rendering/transport option**, never a guarantee that one ordinary image generation can create sixteen legible 1080×1920 pages. A 4×4 collage at 1080×1920 *overall* yields 270×480 per cell, whereas a 1080×1920-per-cell collage requires 4320×7680 overall. In a renderer with insufficient native output resolution, four 2×2 batches or individual pages are required; upscale is not lossless recovery.

**Critical approval conflict:** CC-UPMP v0.08.00 §28 still directs operators to the *v0.04.00* comic file and §29 still describes a five-page standard. The new CC-03.01 cannot, by self-declaration, supersede that. See §6 for an explicit *proposed*, minimally scoped master amendment. One-off sixteen-page orders already satisfy the old explicit-count exception; a new standing default requires editorial decision.

**Proposed §30 insertion (do not replace existing geometry/challenge rules):**

> A 16-page 4×4 collage is only a batch/transport option. ## 7. Geometry, word-size and no-loss verification

### 7.1 Exact no-gutter math

For each portrait page `W/H = 9/16` and C columns / R rows, `composite_width = C·W`, `composite_height = R·H`, and aspect `9C:16R`. Thus:

| Configuration | At 1080×1920 **per cell** | Result |
|---|---|---|
| 4 pages, 2×2 | 2160×3840 | Four legitimate 1080×1920 cells if rendered and inspected. |
| 8 pages, 2×4 | 2160×7680 | Eight cells; high capacity requirement. |
| 16 pages, 4×4 | **4320×7680** | **33,177,600** native pixels; aspect outer 9:16 but not automatically within tool limits. |
| 16 pages, 2×8 | 2160×15360 | Aspect 9:64, even taller transport sheet. |
| 16 pages, 1×16 | 1080×30720 | Aspect 9:256, likely impractical in many generators. |
| 16 pages, 4×4 overall 1080×1920 | **270×480 native pixels per cell** | This is *not* the target native page; enlarge does not restore original detail. |

Additional gutters/outer margins change exact outer ratio; cut bounds must include those measured values. `cc_comic_collage_v008.py` implements a tested **geometry-and-file** workflow; it does not inspect semantic continuity, typography or challenge leakage. Its named crop files are **actually generated only if the operator executes the script with a real input sheet**.
