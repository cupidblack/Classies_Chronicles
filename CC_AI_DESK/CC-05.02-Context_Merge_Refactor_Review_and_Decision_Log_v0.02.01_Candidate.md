## 4. Original vs alternative proposals

The compiled GitHub proposal proposes `RELATE`, `CHOOSE`, `RECONCILE`, `PROVE` as steps; those terms may describe useful work inside canonical `CONNECT`, `TRANSFORM`, `PRESERVE`, `VALIDATE` and `REGISTER`, but replacing the master step names would create a second incompatible contract. A shorter checklist is useful as a quick reference but cannot replace the full 8-step trace and source fields. ChatGPT v0.02.00's clear merge-trace and rejection semantics are adopted in this updated specialist. Claude v0.09.02's caution about unseen master gates and source partial reads is resolved where the corresponding master gate text is visible, but a source extraction is **not** falsely represented as an immutable file download.

## 5. Static acceptance checks and live gaps

Documentary assertions: the v0.02.01 CME must name master/ledger/runbook correctly; list the eight verbs once in canonical order; list all six exact governed stage names; preserve ordinary one-V6 output; define a stage trace and hard-anchor test; prohibit fabricated sources and private challenge-key leakage; cite all twenty-four decisions in this review. The actual local validator and outcomes are in CC-02.04. Not executed as part of this documentary review: a real V1–V6 story pilot, exact source licensing investigation, fully checked live course/verse/study plans, rights proof, secure challenge system, actual repository migration and human acceptance.
